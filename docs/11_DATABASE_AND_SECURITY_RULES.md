# Правила базы данных и безопасности

## База

- PostgreSQL.
- Основные ID — UUID.
- Все сущности имеют created_at, изменяемые — updated_at.
- Важные сущности используют soft delete.
- Внешние ключи и уникальные ограничения задаются в БД.
- На частые фильтры добавляются индексы.

## Деньги

Использовать integer в копейках либо numeric/decimal. Float и double запрещены.

## Остатки

Ручное поле «остаток» не является источником истины. Остаток рассчитывается по движениям и резервам. Допускается кэш или агрегированная таблица, которую можно полностью восстановить.

## Транзакции

Транзакционно выполнять резерв, снятие резерва, загрузку, списание, перемещение, приёмку, возврат и фиксацию платежа с пересчётом статуса.

## Идемпотентность

Повторный запрос не должен дважды списывать, резервировать, загружать, принимать платёж или отправлять одно уведомление.

## Авторизация

- Серверные проверки ролей.
- RLS при использовании Supabase.
- Безопасные сессии.
- Заблокированные профили не получают доступ.

## Файлы

Проверять размер и MIME, использовать закрытое хранилище и временные подписанные ссылки. Административные ключи запрещены в клиентском коде.

## Аудит

Фиксировать создание, редактирование, статусы, цены, платежи, резервы, списания, перемещения, инвентаризации, роли, отмены и возвраты. Аудит нельзя удалять обычным пользователям.
